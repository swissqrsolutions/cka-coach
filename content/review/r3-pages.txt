cat <<'EOF' | kubectl apply -f -

  replicas: 1
  selector: {matchLabels: {app: api}}
  template:
    metadata: {labels: {app: api}}
    spec:
      containers:
      - name: nginx
        image: nginx:1.27-alpine
        ports: [{containerPort: 80}]
        livenessProbe:
          httpGet: {path: /, port: 8080}
          initialDelaySeconds: 3
          periodSeconds: 3
          failureThreshold: 2
EOF

SOLVE IT, STEP BY STEP:
0. Start of every question: in Killercoda just k get nodes (exam: ssh line first)

   $ kubectl -n web describe pod -l app=api | grep -i -A2 liveness
   YOU SEE: Liveness probe failed: ... :8080 ... connection refused
   Probe checks port 8080 but nginx uses 80.
3. Fix the probe port
   $ kubectl -n web patch deploy api --type=json -p='[{"op":"replace","path":"/spec/template/spec/containers/0/livenessProbe/httpGet/port","value":80}]'
   YOU SEE: deployment.apps/api patched
   Probe now checks the right port.
4. Check
   $ kubectl -n web rollout status deploy api
   $ kubectl -n web get pods
   YOU SEE: RESTARTS 0
   New pod stays healthy.
5. Check it works
   $ kubectl -n web get deploy api -o jsonpath="{.spec.template.spec.containers[0].livenessProbe.httpGet.port}"

TRAPS TO AVOID:
- Changing containerPort instead of the probe port
- Removing the probe entirely (changes behaviour, may fail the check)
- Editing the pod instead of the deployment

VERIFY AGAINST THE QUESTION:
- no more restarts: $ k -n web get pods  → must see: new pods Running, RESTARTS 0
- probe on 80: $ k -n web get deploy api -o jsonpath='{.spec.template.spec.containers[0].livenessProbe.httpGet.port}'  → must see: 80

MEMORISE (fast version, target 4 min):

- puts all resources in namespace shop-prod,
- adds the name prefix prod-,
- sets the replicas of Deployment shop to 3.
Apply the overlay with kubectl.
WRITE DOWN: overlay dir = /root/shop-kustomize/overlays/prod · namespace = shop-prod · namePrefix = prod- · replicas shop = 3

SPOT THE PATTERN: Write a Kustomize overlay (resources, namespace, prefix, replicas)
  "uses the base" → resources: - ../../base
  "puts all resources in namespace shop-prod" → namespace: shop-prod (create the namespace if missing)
  "adds the name prefix prod-" → namePrefix: prod-
  "sets the replicas of Deployment shop to 3" → replicas: - name: shop count: 3 (original name, not prod-shop)

IN PLAIN WORDS:
Make a "prod" version of some YAML with a different namespace, name prefix and replica count.

SET UP IN KILLERCODA:
mkdir -p /root/shop-kustomize/base
cat <<'EOF' > /root/shop-kustomize/base/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata: {name: shop}
spec:
  replicas: 1
  selector: {matchLabels: {app: shop}}
  template:
    metadata: {labels: {app: shop}}
    spec: {containers: [{name: shop, image: nginx:1.27-alpine}]}
EOF
cat <<'EOF' > /root/shop-kustomize/base/kustomization.yaml
resources:
- deployment.yaml
EOF

SOLVE IT, STEP BY STEP:
0. Start of every question: in Killercoda just k get nodes (exam: ssh line first)
1. Look at the base
   $ cat /root/shop-kustomize/base/*.yaml
   Know what you are changing.
2. Write the overlay
   $ mkdir -p /root/shop-kustomize/overlays/prod
   $ cat <<'EOF' > /root/shop-kustomize/overlays/prod/kustomization.yaml
resources:
- ../../base
namespace: shop-prod
namePrefix: prod-
replicas:
- name: shop
  count: 3
EOF
   replicas uses the ORIGINAL name, without prefix.
3. Preview
   $ kubectl kustomize /root/shop-kustomize/overlays/prod
   YOU SEE: name: prod-shop  namespace: shop-prod  replicas: 3
   Check output before applying.
4. Apply
   $ kubectl create namespace shop-prod
   $ kubectl apply -k /root/shop-kustomize/overlays/prod
   $ kubectl -n shop-prod get deploy
   YOU SEE: prod-shop  3/3
   -k = apply a kustomization folder.
5. Check it works
   $ kubectl -n shop-prod get deploy prod-shop

TRAPS TO AVOID:
- Using name prod-shop in replicas (use the base name shop)
- k apply -f instead of -k
- Namespace shop-prod doesn't exist → apply fails

VERIFY AGAINST THE QUESTION:
- render OK: $ k kustomize /root/shop-kustomize/overlays/prod  → must see: namespace shop-prod, name prod-shop, replicas: 3
- applied: $ k -n shop-prod get deploy prod-shop  → must see: 3/3
